# 木盒里的木块

配套：[AGENTS.md](../AGENTS.md) · [ENGINEERING.md](./ENGINEERING.md)

底座仍是竖屏 WebGPU，设计空间 **390×844**。这篇是当前玩法方案，替换原来的「冰块救人」。

## 1. 项目

一只木盒里平铺着原色木块。玩家看见盒和块，看不见格子。一整关是一个谜题。木块用自己的形状挡住彼此的出路，棋盘上也可以有固定阻挡。固定阻挡和「冰块救人」里的岸是同一件事：占着格子，自己不动，挡在离开方向上就出不去。两套方案的底层逻辑相同，包装不同。冰块那套不再作为当前方案。

玩家只做一件事：从现在抽得出的木块里选一块，沿它伸出去的那一头抽出盒子。可抽的木块都离开，这一关过。固定阻挡留在棋盘上。

## 2. 包装

木头。木盒，原色木块。没有动物，没有彩绘，没有角色。

方向就是木块自己伸出去的那一头。不另画箭头，不靠脸。

## 3. 规则

一块有一个离开方向，就是伸出去的那一头。这个方向上还有别的木块，或者有固定阻挡，它就抽不走。抽走占路的木块，下一块的方向才通。固定阻挡抽不走。

形状决定挡住谁。一块横条可以同时挡住上、下两块的出口。先抽横条，两块一起通。先抽旁边已经通的那块，横条还在，那两块仍然出不去。

同一时刻至少有两块方向是通的。先抽哪一块，后面松开的不是同一条。抽走的木块离开画面，不放回来。

每一关开始都要方正。外轮廓是方形或长方形。木块和固定阻挡对齐格子摆满这块区域，不斜放，不开局就缺一块角。格子不画出来。

看一眼能指出哪几块现在能抽，并且知道抽完会离开。固定阻挡看起来就是盒子的一部分，不会被当成能抽的木块。

## 4. 一局

点一块方向已经通的木块，它沿自己的那一头抽出盒子。点一块方向还被占着的木块，它不动。

没有倒计时，没有生命，没有第二种操作。不旋转木块，不把木块挪到盒子里的另一个位置。

## 5. 关卡

一关写明每块木块的形状、位置和离开方向，以及固定阻挡占哪些格。方向只有四个：上、下、左、右，由伸出去的那一头决定。固定阻挡没有离开方向。

能进关卡的样子要同时满足三件事：一眼能看出哪一头是出口；至少有两块在开局就能抽；先抽的那一块会改变后面哪一条通。只有一条顺序的塔不进包。每块只挡住自己正前方一条、形状不承担阻挡的关卡不进包，那是停车。

木块之间不重叠，也不和固定阻挡重叠。抽出之后不再占位。开局的外轮廓要是方的或长方的。

## 6. 不做

不加颜色配对，不加另画的箭头和缺口，不加减转动。不用乐高凸点的一层盖一层。不用雪花片和孔明锁。不用小动物彩绘。

不加道具、空位、倒计时、生命。不把「看广告，否则这关做不完」写进规则。

## 7. 落在底座上

玩法放在 `src/game/`。UI 只挂 `#ui-root`。木盒按设计空间排在舞台里，不跟窗口像素走。触控用 `clientToDesign`，letterbox 外的点丢掉。

先做能玩的一关：开局外轮廓是方的。两块开局就能抽，一块横条同时挡住另外两块的出口，一侧用固定阻挡堵住。点通了的块会离开，点被挡住的块和固定阻挡都不动。可抽的木块都离开才过关。震动和音效不进这一步。画面上不放倒计时、金币、心、奖励按钮。
