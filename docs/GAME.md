# 木盒里的木块

配套：[AGENTS.md](../AGENTS.md) · [ENGINEERING.md](./ENGINEERING.md)

当前玩法规范。第一关在 `src/game/`。底座约定不变：设计空间 **390×844**，`base: './'`，无 WebGPU 则失败。开发地址 `http://127.0.0.1:5193/`。

格子坐标：列向右增大，行向下增大。左上角是 `(0,0)`。

## 1. 词汇

| 词 | 含义 |
|----|------|
| 托 | 外圈木盒，不占格子，不能抽 |
| 木块 | 占若干格，有一个离开方向，可以抽走 |
| 固定阻挡 | 占若干格，没有离开方向，和托连在一起 |
| 离开方向 | 上、下、左、右之一。这一块只能沿这一侧滑出 |
| 通 | 沿离开方向扫出外轮廓时，扫过的格上没有别的木块，也没有固定阻挡 |

## 2. 规则

一块只有一个离开方向。沿这个方向每次平移一格，直到所有格都出了外轮廓。扫过的格里有别的木块或固定阻挡，就不通。路上可以有多块。挡路的都离开之后，这一块才通。固定阻挡永不离开。

朝盒子内部伸出的臂只负责挡路，不算第二个出口。直条两头一样宽，出口就是离开的那一侧，不多占一格。不承担阻挡的凸起不放。

木块和固定阻挡对齐格子摆满一块方形或长方形区域，互不重叠，不斜放，不缺角。格子不画出来。抽走的木块离开画面，不再占格，也不能放回来。

开局至少有两块是通的。先抽哪一块，下一手先松开的不是同一批。只有一条强制顺序的关不进包。每块只挡住自己正前方一条、形状不负责同时挡住多块的关不进包。

过关：木块全部离开。固定阻挡留下。没有步数、时间、生命。

## 3. 操作

按住拖动。听 `#stage` 的指针事件，并捕获这只指针。第二只手指不开始新手势。

设计坐标用舞台矩形：

```
dx = (clientX - stageRect.left) / layout.scale
dy = (clientY - stageRect.top) / layout.scale
```

出了 0…390 × 0…844 的按下丢掉。已经抓住木块之后，手指滑出这块区域，位移照常计算。`pointerup` 和 `pointercancel` 都结束这一手；没有提交就弹回。

未满 6 设计像素不判定方向。离开方向上的分量更大，且朝向出口，才算方向对。

| 情况 | 占格 | 画面 |
|------|------|------|
| 方向不对 | 不变 | 不跟手。视觉子节点挤扁后弹回，约 0.15 秒，每手一次 |
| 方向对，路不通 | 不变 | 只沿出口跟手，最多 0.15 格，松手弹回 |
| 方向对，路通，松手不足 0.55 格 | 不变 | 弹回 |
| 方向对，路通，松手达到 0.55 格 | 这块移出 | 沿出口滑出外轮廓再隐藏 |

拖动中只改视觉位置。组节点的占格位置不参与挤压和抖动。相机不跟着木块动。这一关不接音效和震动。木块清空后停止输入，不放结算按钮。

命中用设计坐标对到格，不用射线。俯仰不是 0° 时，画面上的块和设计格会错开，命中仍按格子，不跟着相机。侧面不是把手。

## 4. 外形

世界坐标和设计坐标是同一套：`x` 向右，`y = -设计 y`，行向下是世界 `-y`。相机是正交，再绕横轴俯仰。默认俯仰 **15°**。斜切写在 `updateProjectionMatrix` 末尾，基准块高 14 时侧面约 4 设计像素；块加高后侧面按比例变长。每次改高度或俯仰，把木盒中心重新摆回画面中央。

整盘 5×5 在 390×844 里居中。格距 64。同一块木块的格子连成一块，内部不留缝。块与块之间、块与固定阻挡之间的缝是 4。

每块一个挤出网格。外凸角半径 **10**，凹角保持尖。侧面圆角：上下厚度 **5**，水平扩展 **3.2**，弧分 8 段。倒角前轮廓再内收水平扩展量，缝仍是 4。网格基准高 14，底面在 `z = 2`，显示高度用 `z` 缩放。默认块高 **40**，顶面在 `z = 42`。

每块一块竖向木纹，木色只用来分辨是哪一块，不参与规则。不画箭头。块下有一层淡阴影，跟着视觉子节点。主光从画面左上方来，下沿比顶面暗。

托是圆角木框，带唇边。固定阻挡和托同一套深木色，顶面低于木块底边。`#ui-root` 上有块高（4…48）和俯仰（-30°…30°）两条调节，只改外观。

## 5. 第一关

5×5。右列 `(4,0)`…`(4,4)` 是固定阻挡。

```
C C C H #
C A A H #
C M M P #
C B B P #
C C C C #
```

| 块 | 格（列, 行） | 方向 | 开局挡住它的 |
|----|----------------|------|----------------|
| C | (0,0) (1,0) (2,0) (0,1) (0,2) (0,3) (0,4) (1,4) (2,4) (3,4) | 左 | 无 |
| H | (3,0) (3,1) | 上 | 无 |
| A | (1,1) (2,1) | 上 | C |
| B | (1,3) (2,3) | 下 | C |
| P | (3,2) (3,3) | 上 | H |
| M | (1,2) (2,2) | 下 | B 和 C |

抽 C：A 和 B 一起通，M 仍要等 B 离开。抽 H：只有 P 通，A 和 B 仍被 C 挡住。两条路都能把木块清完。

C 同时占住上盒口和下盒口，所以能挡住向上的 A 和向下的 B。中间单独一行做不到这一点。

## 6. 不做

不加颜色配对、动物彩绘、冰块和数字。不画箭头。不旋转，不把木块放到盒子里的另一格。不加道具、空位、倒计时、生命和广告。调节条不是玩法界面。

## 7. 代码

| 文件 | 内容 |

| `src/game/level.ts` | 占格、方向、扫出盒外。启动时核对开局阻挡表 |
